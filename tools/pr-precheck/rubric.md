# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Plan fidelity | Plan context or plan.md with deviations, compared with every diff hunk and description claim | Every change and omitted planned behavior is accounted for by the plan or an explicit justified deviation; judge scope by behavior and responsibility, not exact wording or requiring each implementation detail to be separately named; no silent scope expansion or reduction. Disclosed bounded shortfalls can pass; a claim of exact fidelity contradicted by the diff fails. | required |
| Claim accuracy | Title, description, checklist compared with diff and test output | Factual claims match the supplied artifacts: claimed tests are represented, negative claims match the diff, and claimed behavior agrees with the recorded observations. Accept concrete run summaries under Observable validation; do not independently reject them for missing raw logs. Do not infer contradictions from unseen helper implementations or omitted caller context. Honest limitations pass; material contradictions and success claims with no concrete validation fail. | required |
| Observable validation | Repro and plan test plan compared with test-evidence commands and results | A reproducible issue-specific action or command is paired with a concrete before/after observation that distinguishes the bug from the intended outcome; relevant controls and the named repository suite have recorded outcomes. Precise textual UI observations and command-linked result summaries count, even without a raw terminal transcript. A named suite plus a reported outcome can establish suite execution when accompanied by decisive repro evidence; a bare “tests pass” alone or only an unrelated happy-path test cannot. Require only checks named by that package’s plan or repository, never Path Review commands for other repositories. Disclosed bounded failures or omissions can pass when the demonstrated result is clear and broader success is not claimed. Require separately promised test fixtures to exist, but do not invent exhaustive cases beyond the plan. | required |
| Reviewable diff | Full diff and commits compared with issue and plan | The fix is identifiable without unrelated cleanup, formatting churn, debug leftovers, dead or commented-out code, or unexplained generated artifacts. Necessary related changes are allowed. Disclosure alone does not justify unrelated edits. | required |
| Repository standards | Repo-facts template/policy and thread direction, or live PR template and docs/CONTRIBUTING.md, compared with PR text and diff | All explicitly applicable repository requirements are met, including substantive template sections, required changelog/docs, and any stated AI disclosure or prohibition. Explain genuine non-applicability. Do not invent requirements where no policy exists. In live course work require the course AI-use disclosure in Notes for Reviewers. | required |
| Reviewer clarity | Title and description | The purpose, resulting behavior, and any limitations are understandable without reconstructing the conversation; concise text is sufficient. | preferred |

## Verdict rule

Return accept only when every required check passes. Any required fail or unclear produces reject. Preferred grades never change the verdict. Missing required evidence is fail; ambiguous evidence is unclear. Honest disclosure can satisfy the checks as specified above, but cannot excuse unrelated changes or override explicit repository policy. No score or third verdict is emitted.
