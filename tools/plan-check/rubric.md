## Checks

| Check | Evidence | Pass condition | Weight |
| ----- | -------- | -------------- | ------ |
| diagnosis | The plan's stated cause, read against the repro-evidence block's observed behavior and reproduction results. | The plan identifies the cause of the bug, and that cause is consistent with the reproduction evidence. | required |
| scope | The plan's scope and proposed-changes statements, including the components or files it says it will change and anything it says it will leave unchanged. | The plan explicitly identifies the components or files in scope and clearly bounds the change by stating what related work is out of scope. | required |
| test | The plan's test plan, read against the original steps and observable failure in the repro-evidence block. | The plan specifies an automated or manual test that reruns the original reproduction or maps directly to its steps and demonstrates that the reported bug no longer occurs. | required |

## Verdict rule

Accept (ready) only if every required check passes. Reject (hold) if
any required check fails or is unclear. Preferred checks, if added,
never change the verdict.
